# 产品验收标准

> 本规则定义了产品交付前的验收检查清单，在代码审查和上线前执行。

## 何时触发

以下场景必须执行产品验收：
- 功能开发完成（代码审查通过后、合并前）
- 版本发布前
- 用户验收测试（UAT）阶段

## 验收 Checklist

### A. 功能完整性
- [ ] 所有 PRD/用户故事中的验收条件均已满足
- [ ] 功能边界清晰：该做的做了，不该做的没做
- [ ] 正常流程可走通（Happy Path 完整闭环）
- [ ] 所有按钮/链接/入口有明确的交互反馈

### B. 异常与边界
- [ ] 网络异常时有合适的错误提示（不是白屏或崩溃）
- [ ] 数据为空时有空状态设计（不是空白页面）
- [ ] 数据加载中有 Loading 状态（骨架屏或 spinner）
- [ ] 输入边界：空输入、超长输入、特殊字符均有处理
- [ ] 权限不足时有明确引导（不是死胡同）

### C. 用户体验
- [ ] 交互流程符合用户心智模型（操作步骤 ≤ 主流竞品）
- [ ] 关键操作有二次确认（删除、支付、取消等不可逆操作）
- [ ] 操作有反馈（成功/失败 toast 或提示）
- [ ] 页面跳转逻辑正确（返回不丢数据、不跳死循环）

### D. 无障碍访问（WCAG 2.1 AA 基础）
- [ ] 所有交互元素可通过键盘访问（Tab/Enter/Escape）
- [ ] 图片有有意义的 alt 文本
- [ ] 表单控件有 label 关联
- [ ] 颜色不是传达信息的唯一方式（色盲友好）
- [ ] 页面有合理的标题层级（h1 → h2 → h3）

### E. 性能感知
- [ ] 首屏加载时间可接受（< 3 秒为用户感知阈值）
- [ ] 操作响应时间有反馈（点击后 200ms 内无反馈 = 用户觉得卡）
- [ ] 列表/表格有分页或虚拟滚动（> 100 条数据时）

### F. 兼容性与一致性
- [ ] UI 风格与现有产品一致（字体、间距、颜色、圆角）
- [ ] 文案风格一致（同一事物用同一名称）
- [ ] 目标浏览器/设备下渲染正常

### G. 安全与隐私
- [ ] 用户敏感信息有脱敏处理（手机号、身份证、银行卡）
- [ ] 无在前端暴露的调试信息/API Key
- [ ] 第三方 SDK/脚本按需加载

## 验收报告模板

```markdown
## 产品验收报告：「{功能名}」

**验收日期**：YYYY-MM-DD
**验收人**：{姓名}
**版本号**：v{X.Y.Z}

### 验收结果

| 类别 | 总项 | 通过 | 未通过 | 不适用 |
|------|:----:|:----:|:------:|:------:|
| 功能完整性 | | | | |
| 异常边界 | | | | |
| 用户体验 | | | | |
| 无障碍 | | | | |
| 性能感知 | | | | |
| 兼容性 | | | | |
| 安全隐私 | | | | |
| **合计** | | | | |

### 未通过项
| 编号 | 类别 | 问题描述 | 严重级别 | 建议方案 |
|------|------|----------|:--------:|----------|
| 1 | | | P0/P1/P2 | |

### 验收结论
- 🟢 **通过**：所有 P0 项通过，可以发布
- 🟡 **有条件通过**：P0 通过但 P1 有遗留，发布后跟进
- 🔴 **不通过**：有 P0 阻塞项，修复后重新验收
```

## 严重级别定义

| 级别 | 定义 | 示例 |
|:----:|------|------|
| P0 | 阻塞发布 | 支付流程中断、数据丢失、白屏崩溃 |
| P1 | 影响体验但可发布 | 空状态缺设计、某个浏览器样式问题 |
| P2 | 优化建议 | 文案可更友好、动画可更流畅 |
