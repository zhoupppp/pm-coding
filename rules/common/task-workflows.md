# 非研发任务工作流

> 由全局 CLAUDE.md 引用。数据分析、工作汇报、会议纪要、调研洞察、学习研究场景自动加载本文件。

---

## 📊 数据分析：5 步流程

```
需求确认 → 数据获取 → 清洗分析 → 结论验证 → 报告输出
```

- **需求确认**：明确分析目标、数据来源、期望输出格式（Excel / HTML / 图表）
- **数据获取**：确认数据可用性、完整性、时效性
- **清洗分析**：处理缺失值、异常值，执行分析逻辑
- **结论验证**：交叉验证关键数据，标注「推测」vs「确定」
- **报告输出**：关键发现 → 数据支撑 → 建议行动。HTML 报告用 Lucide SVG 图标，图表优先 ECharts

## 📈 工作汇报：4 步流程

```
受众确认 → 结构设计 → 内容生成 → 视觉打磨
```

- **受众确认**：给谁看？决策层（结论先行）还是执行层（要细节）？关注什么指标？
- **结构设计**：先列大纲和叙事逻辑——金字塔原理还是时间线叙事？
- **内容生成**：按大纲填充内容。数据要有来源，结论要有支撑。一页一个论点。生成后自检——所有数字是否有来源？结论是否与数据一致？
- **视觉打磨**：PPT 走 `GordenSuperPPTSkill` 或 `supir-slides`，HTML 报告走 Lucide SVG + 响应式布局

**输出规范**：标题页（主题+日期+受众）→ 摘要页（30 秒核心结论）→ 正文（一页一论点）→ 行动页（需要听众做什么）

---

## 📝 会议纪要：3 步流程

```
输入确认 → 要点提炼 → 行动项输出
```

- **输入确认**：客户会议还是内部会议？有录音/文字记录吗？
- **要点提炼**：会议主题 / 参与方 / 核心结论 / 关键讨论点（按议题分组）
- **行动项输出**：Who / What / When，可追踪格式
- 客户/投资人相关会议必须做脱敏处理

---

## 🔍 调研洞察：4 步流程（轻量级）

> 本流程适用于快速调研（了解概念、技术选型、查资料）。专业的 PM 产品调研（SWOT/BMC/用户画像/竞品深度分析等）→ 走 `rules/common/pm-workflows.md`。

```
范围界定 → 多维收集 → 交叉验证 → 洞察输出
```

- **范围界定**：研究什么？多深？目的是决策支撑还是知识积累？
- **多维收集**：GitHub（代码实现）→ 官方文档（API 能力）→ WebSearch（行业动态）→ 竞品对比
- **交叉验证**：关键数据至少两个来源交叉确认，单一来源必须标注
- **洞察输出**：「事实」vs「判断」严格分开。事实标来源，判断标置信度。结论必须有行动建议

---

## 📚 学习研究：3 步流程

```
问题定义 → 分层解释 → 应用验证
```

- **问题定义**：我想理解什么？当前已知什么？困惑点在哪？
- **分层解释**：一句话总结 → 核心原理 → 代码/实例 → 延伸阅读
- **应用验证**：能用在当前项目哪里？给一个具体可操作的案例
