# 产品研发：7 步生产流程

> 由全局 CLAUDE.md 引用。产品研发类任务自动加载本文件。

任何涉及代码变更的任务，必须走此流程。上一步门禁不通过，不进入下一步。

```
需求澄清 → 规格定义 → 架构设计 → 编码实现 → 测试验收 → 安全审查 → 上线检查
```

---

### Step 1: 需求澄清
**触发条件**：需求模糊、只有一句话、涉及多角色、涉及数据/隐私、涉及外部系统

遇到以下信号必须先提问，不能直接动手：

| 信号 | 必须澄清 |
|------|---------|
| 需求只有一句话 | 5W1H 追问（谁、什么场景、什么结果、为什么、什么时候、怎么算完成） |
| 有「优化」「改进」等模糊词 | 追问当前问题和期望指标 |
| 涉及多角色 | 追问每个角色完整流程 |
| 涉及数据/隐私 | 追问来源、脱敏、合规要求 |
| 涉及外部系统 | 追问 API 文档、认证方式、错误码 |

**门禁**：用户故事 + 验收条件 + 「不做什么」边界已输出并获确认

### Step 2: 规格定义
**强制输出规格卡**（模板见 `~/.claude/templates/spec-card.md`）：

| 维度 | 内容 |
|------|------|
| 功能名称 | 一句话 |
| 用户故事 | 作为...我想要...以便... |
| 验收条件 | [ ] / [ ] / [ ]（可测试的 Given-When-Then 格式） |
| 边界约束 | 不做什么、数据量上限、并发上限 |
| 错误场景 | 网络异常时 / 数据为空时 / 权限不足时 |
| 成功指标 | 如何判断做对了（可测量） |
| 风险点 | 可能出问题的地方及其影响 |
| 回滚方案 | 出问题怎么退回去（模板见 `~/.claude/templates/rollback-plan.md`） |

**门禁**：8 个维度全部填写，用户已确认

### Step 3: 架构设计
**触发条件**：涉及 3+ 文件、新增服务/模块、数据库变更、引入外部依赖
**输出**：ADR（架构决策记录）+ 技术方案，包含：方案描述、替代方案对比、风险与权衡、受影响模块列表
**门禁**：方案已获用户确认

### Step 4: 编码实现
- 按规格卡写代码，不超范围实现
- 核心业务逻辑走 TDD（Red → Green → Refactor）
- 探索性/原型代码可声明豁免 TDD（需在任务开始时声明）
- **强制规范**：
  - 所有外部调用有超时和重试策略
  - 所有异常必须处理或传播，禁止空 catch
  - 禁止硬编码密钥、令牌、密码
  - P0 数据（个人身份信息）不出现在日志和错误信息中
  - 所有公开函数有规格注释（输入、输出、副作用、异常）

#### 编码质量原则

以下三条约束 Claude 写出什么样的代码。源自 Andrej Karpathy 对 LLM 编码常见失败模式的观察。

**简洁优先（Simplicity First）**
- 用最少的代码解决当前问题，不添加未要求的特性
- 不为单次使用创建抽象层（别写「万一将来要用」的代码）
- 如果本应 50 行的代码写了 200 行——重写它
- 自检：「一个资深工程师会说这段代码过度设计吗？」

**精准改动（Surgical Changes）**
- 每一个被修改的行必须能追溯到用户的具体需求
- 修 Bug 时不要顺手改代码风格、变量命名、或无关代码的结构
- 匹配现有代码风格——即使你认为有更好的写法
- 自检：「diff 里的每一行改动，我都能解释它为什么是必要的吗？」

**目标驱动（Goal-Driven Execution）**
- 每个步骤配一个验证检查点：[步骤] → 验证：[检查项]
- 自己写测试 → 自己跑 → 自己修 → 循环直到通过 → 再给用户看
- 不要说「添加了校验」，要说「校验已通过——测试覆盖了空输入、超长输入、SQL 注入字符」
- 自检：「如果有人只读我的验证输出，能否判断功能是否真的完成了？」

> 详见 `rules/common/coding-style.md`、`rules/common/testing.md`

### Step 5: 测试验收
- 规格卡驱动——每个验收条件至少一个测试用例
- Happy Path + 错误路径（网络异常、超时、数据为空、权限不足）必须通过
- 核心逻辑覆盖率 80%+
- UI 变更必须截图留痕（`.test-evidence/` 目录，详见 `rules/common/ui-test-evidence.md`）

### Step 6: 安全审查
**强制触发**：P0 数据操作、认证变更、支付逻辑、新增外部依赖、加密相关代码
**门禁**：security-reviewer 无 CRITICAL 问题

> 详见 `rules/common/security.md`

### Step 7: 上线检查
**门禁**（详见 `~/.claude/checklists/production-gate.md`）：
- 回滚方案已确认
- 监控指标已配置
- 相关文档已更新
- 生产环境冒烟测试通过
