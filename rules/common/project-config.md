# 项目级配置规范

> 由全局 CLAUDE.md 引用。进入项目目录时自动执行自检。项目级 CLAUDE.md 模板在此定义。

---

## 项目启动自检流程

进入项目目录后，在开始实际工作前，执行以下检查。**不要等用户告诉你——主动检查、主动提示。**

1. **检查项目 CLAUDE.md**：
   - ❌ 不存在 → 提示：「此项目还没有 CLAUDE.md。请告诉我：(1) 技术栈 (2) 核心业务规则 (3) 需要豁免的全局规则。我会生成约 40-60 行的项目配置。」
   - ✅ 存在但超过 30 天未更新 → 提示：「CLAUDE.md 已 N 天未更新。当前项目阶段是否有变化？是否需要更新？」
   - ✅ 存在且最新 → 加载，进入下一步。

2. **检查关键引用是否失效**：
   - CLAUDE.md 中引用的文档路径是否存在？

3. **检查项目记忆**：
   - 是否有项目记忆记录？首次进入 → 提示确认基本信息。

4. **检查 rules/ 文件完整性**：
   - `~/.claude/rules/common/` 下的关键文件是否存在。

## 项目 CLAUDE.md 模板（约 40-60 行）

遵循「**只写 Claude 无法从代码中自动发现的内容**」原则：
- 不重复全局已有的通用规则
- 不重复代码中已有的信息
- 只写：差异、例外、业务规则、踩过的坑、当前阶段

```markdown
# [项目名]

## 项目定位
一句话：（做什么、为谁做）

- 语言/框架/运行时：

- 关键外部服务：

## 全局例外

| 全局规则 | 本项目处理 | 原因 |
|---------|-----------|------|
| （如无例外，写「本项目全部适用全局规则」） | | |

## 核心业务规则
1.
2.
3.

## 禁止做什么（本项目踩过的反模式）
-
-

## 关键引用文档（按需引用，不内嵌）
- 产品需求：@docs/product.md
- 设计规范：@docs/design.md
- 架构决策：@docs/adr/

## 当前阶段
- 版本：vX.Y
- 当前首要目标：

```

## 规范继承规则

```
全局 CLAUDE.md           ← 宪法，一次配置，所有项目自动继承
  ↓
rules/common/            ← 自动加载的规则库（本目录下所有 .md 文件）
  ↓
项目 CLAUDE.md           ← 只写差异（技术栈/业务规则/例外），约 40-60 行
  ↓
@docs/product.md 等       ← 详细文档，CLAUDE.md 引用后按需读取
```

**优先级**：项目 CLAUDE.md > rules/common/ > 全局 CLAUDE.md

**维护原则**：
- 全局规则按需更新（踩坑后加到对应 rules/ 文件）
- 项目 CLAUDE.md 只有技术和业务变了才需要改
- 详细文档（product/design/adr）按需维护
