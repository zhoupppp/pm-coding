# Claude Code 生产级 AI 产品研发引擎

> 让 Claude Code 从「写代码的助手」变成「能帮你把关的产品研发伙伴」。

---

## 这是什么？

一套 Claude Code 的全局配置体系。装上之后，你的 Claude Code 会：

- 🧭 **自动识别 9 种工作场景**：产品定义、研发、数据分析、汇报、会议、调研、学习、文档、咨询——不再对所有任务用同一套流程
- 🛡️ **高风险操作主动确认**：删数据库、推送生产分支……先问你，不先动手
- 📋 **写代码前先出规格卡**：确认「要做对的事」再动工，不会闷头瞎写
- 🔍 **能检测自己的幻觉**：引用不存在的 API 或文件时自己暂停验证
- 🏗️ **自动检查项目配置**：打开新项目时主动提示你缺什么、该更新什么

**一句话：你不需要每次都说「先别写代码，先想清楚」——规则已经替你说了。**

## 快速开始

### 1. 安装

```bash
# 克隆到 Claude Code 配置目录
git clone https://github.com/zhoupppp/pm-coding.git ~/.claude-config

# 部署规则文件
cp ~/.claude-config/CLAUDE.md ~/.claude/
cp -r ~/.claude-config/rules/common/ ~/.claude/rules/common/
cp -r ~/.claude-config/templates/ ~/.claude/templates/
cp -r ~/.claude-config/checklists/ ~/.claude/checklists/
```

**或者**运行一键脚本：

```bash
bash ~/.claude-config/setup-portable.sh
```

### 2. 验证安装

重启 Claude Code，在新会话中输入：

```
请读取 ~/.claude/CLAUDE.md 的第一行标题
```

预期输出：`# 生产级 AI 产品研发引擎`

### 3. 开始使用

直接用就行了。Claude 会自动判断你的任务类型并走对应流程。

| 我想…… | 直接说 | Claude 会自动…… |
|--------|--------|----------------|
| 开发新功能 | 「帮我加一个用户反馈接口」 | 先澄清需求 → 出规格卡 → 等你确认 → 写代码 |
| 做竞品分析 | 「看看竞品 X 的会员体系」 | 走 PM 工作流 → 调竞品分析工具 → 出对比报告 |
| 写 PRD | 「帮我写一份产品方案」 | 走产品定义流程 → 出结构化 PRD |
| 跑数据 | 「分析这份销售表」 | 走数据分析流程 → 先确认数据格式 → 再分析 |
| 做 PPT | 「给 CTO 做一份技术进展 PPT」 | 先确认受众 → 列大纲 → 生成内容 → 视觉打磨 |
| 紧急修 Bug | 「生产环境有个 Bug，马上修」 | 快速模式 → 先写复现测试 → 修复 → 验证 |
| 快速问个问题 | 「/quick 这个 SQL 怎么写」 | 跳过所有流程，直接回答 |

| ✉️ 文档草拟 | 邮件、通知、方案 | 直接输出 + 脱敏 |
| 💬 快速咨询 | 问定义、快速确认 | 直接回答 + 置信度 |

## 安全机制

| 遇到这种情况 | Claude 的行为 |
|-------------|-------------|
| 你要删数据库字段 | ⚠️ 先弹确认：操作/影响/风险/回滚，等你点头 |
| 你要推生产分支 | ⚠️ 同上，P0 封控 |
| 你要改支付/认证代码 | ⚠️ 同上，强制走安全审查 |
| AI 引用了不存在的 API | 🔍 自己检测到 Hallucination，暂停验证 |
| AI 在瞎猜 | 📝 标注「推测」并告诉你如何验证 |

## 项目级配置

每个项目可以有一个自己的 `CLAUDE.md`（放在项目根目录），只需要写和全局规则**不同的地方**：

```markdown
# 项目名

## 技术栈
- 前端：Vue 3
- 后端：Python FastAPI

## 全局例外
本项目是数据分析项目，不适用 TDD 要求。

## 核心业务规则
1. 所有 API 返回格式必须是 { ok, data, error }

## 当前阶段
- v2.1 · 2026-07
```

打开项目时 Claude 会自动检查配置是否存在、是否过期。

## 常见问题

**Q：这套配置会不会让 Claude 变得很啰嗦？**

不会。轻量场景（问定义、写邮件、快速调研）走轻量流程。`/quick` 命令可以跳过所有流程。只有涉及代码变更或产品决策时才会走完整门禁。

**Q：和 Claude Code 默认行为有什么不同？**

默认的 Claude 收到「帮我加个功能」会直接写代码。这套配置会先问清楚、先出规格卡、先确认——因为默认目标是「交付正确的产品」，不是「快速出代码」。

**Q：怎么更新？**

```bash
cd ~/.claude-config && git pull && bash setup-portable.sh
```

**Q：我有一台新电脑，怎么迁移？**

在新电脑上克隆仓库，运行 `setup-portable.sh`。API Key 需要手动配置（`~/.claude/settings.json`）。
