# 代码审查检查清单

> 代码编写完成后、提交前使用。逐项检查，逐项打勾。

---

## 安全审查（CRITICAL — 一项不通过即阻塞）

- [ ] 无硬编码密钥/令牌/密码
- [ ] 无 SQL 注入（所有查询使用参数化）
- [ ] 无 XSS 漏洞（用户输入已转义）
- [ ] 认证/授权检查在每个受保护路由上
- [ ] 敏感数据（P0）未出现在日志/错误信息中
- [ ] 第三方依赖无已知高危漏洞

## 代码质量（HIGH — 两项以上不通过需修复）

- [ ] 函数不超过 50 行
- [ ] 文件不超过 800 行
- [ ] 嵌套不超过 4 层
- [ ] 无空 catch 块（所有异常已处理或传播）
- [ ] 无 console.log 或调试语句
- [ ] 新增代码有测试覆盖
- [ ] 所有公开函数有规格注释

## 编码质量三原则（HIGH）

- [ ] **简洁优先**：没有未要求的特性、没有单次使用的抽象、没有过度设计
- [ ] **精准改动**：每个被修改的行都能追溯到用户需求、没有顺手重构无关代码
- [ ] **目标驱动**：有可验证的检查点、自己跑过测试并确认通过

## 性能（MEDIUM）

- [ ] 无 N+1 查询
- [ ] 有分页或限制的大数据量查询
- [ ] 外部调用有超时配置
- [ ] 无同步阻塞操作

## 风格规范（LOW）

- [ ] 命名清晰描述用途
- [ ] 匹配现有代码风格
- [ ] 无 TODO/FIXME 未关联 Issue
- [ ] 无魔法数字（或已用常量替代）

---

## 审查结果

| 级别 | 数量 | 状态 |
|------|:----:|------|
| CRITICAL | | pass / block |
| HIGH | | pass / warn |
| MEDIUM | | pass / info |
| LOW | | pass / note |

**结论**：
- 🟢 APPROVE — 可以提交
- 🟡 WARNING — 有 HIGH 问题，建议修复后提交
- 🔴 BLOCK — 有 CRITICAL 问题，必须修复
